## Reconciliation rules

1. An import never mutates the Malbec source export.
2. Every source record receives a deterministic legacy key and content hash.
3. Re-running the same export must be idempotent.
4. Conflicting device versions are reported, not silently overwritten.
5. A record missing from one device is not treated as a confirmed deletion because Malbec has no tombstones.
6. Repository seed records are not treated as household history without confirmation.
7. Placeholder cards/toasts are capabilities, not data records.
8. Calendar events are matched against the live Apple calendar before creation.
9. Files are validated by count, byte size, MIME type, and checksum.
10. Financial amounts require transaction/project/vendor reconciliation before reporting.
11. Legacy read-only and sunset work remains blocked until all retained rows are validated.
